# Agent layer — Cloudflare Worker

This Worker adds the four agent-discovery features that **GitHub Pages cannot
produce on its own**, because that host gives you no control over response
headers:

| Feature | Why it needs an edge layer |
| --- | --- |
| `Link` response headers (RFC 8288) | GitHub Pages sends a fixed header set |
| `Accept: text/markdown` negotiation | Needs per-request body swapping + `Vary: Accept` |
| `Content-Type: application/linkset+json` on `/.well-known/api-catalog` | The extensionless file is served as `application/octet-stream` |
| A real MCP endpoint (`/mcp`) | GitHub Pages is static; MCP needs a request handler |

Everything the Worker returns is derived from files the site already publishes.
It does not invent data.

## What it does

1. **Link headers** on every HTML response, pointing at resources that exist:
   `api-catalog`, `service-desc` (`/openapi.json`), `service-doc` (`/docs/api/`),
   and `describedby` for the ARD manifest, agent-skills index and `auth.md`.
2. **Markdown for Agents** — when the request advertises `text/markdown`, it
   returns the real `.md` twin (`/` → `/index.md`, `/motion-graphics.html` →
   `/motion-graphics.md`, …) with `Content-Type: text/markdown; charset=utf-8`
   and `Vary: Accept`. Browsers keep getting HTML.
3. **Linkset content type** on `/.well-known/api-catalog`.
4. **`/mcp`** — a stateless MCP server (JSON-RPC 2.0 over HTTP) with four tools:
   `search_projects`, `get_project`, `list_services`, `get_profile`. It reads
   `/api/*.json` from the origin. Outbound paths are hard-coded, so it cannot be
   used as an SSRF proxy.
5. **`/.well-known/mcp/server-card.json`** — generated by the Worker, so it only
   exists when a real MCP endpoint exists.

## Deploy without a custom domain (works today)

```bash
npm i -g wrangler
cd deploy/cloudflare
wrangler login
wrangler deploy
```

You get `https://ahmed-mokbel-agent-layer.<your-subdomain>.workers.dev`.

Test it:

```bash
curl -sI https://ahmed-mokbel-agent-layer.<sub>.workers.dev/ | grep -i '^link'
curl -s -H "Accept: text/markdown" https://ahmed-mokbel-agent-layer.<sub>.workers.dev/ | head -20
curl -s https://ahmed-mokbel-agent-layer.<sub>.workers.dev/.well-known/mcp/server-card.json | head -20
curl -s -X POST https://ahmed-mokbel-agent-layer.<sub>.workers.dev/mcp \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

> A `workers.dev` host is a **different origin** from `ahmedmokbel99.github.io`.
> The API and MCP work fine there (CORS is `*`), but the `Link` header only
> applies to pages served by the Worker. For a truly single-origin site, use a
> custom domain.

## Deploy with a custom domain (single origin, everything passes)

1. Buy a domain and add it to Cloudflare (free plan is enough).
2. Add it to the repository as `content/site.json` → `meta.customDomain`, e.g.
   `"ahmedmokbel.com"`, then run `python build.py` and push. The build writes
   `CNAME` and points every canonical URL, sitemap entry and API URL at it.
3. In Cloudflare DNS, point the apex at GitHub Pages:

   | Type | Name | Content |
   | --- | --- | --- |
   | A | `@` | `185.199.108.153` |
   | A | `@` | `185.199.109.153` |
   | A | `@` | `185.199.110.153` |
   | A | `@` | `185.199.111.153` |
   | CNAME | `www` | `ahmedmokbel99.github.io` |

   Set these to **DNS only** (grey cloud) first so GitHub can issue the TLS
   certificate. Once GitHub Pages shows "Certificate issued", you may switch to
   **Proxied** (orange cloud) and add the route below.
4. Uncomment `routes` in `wrangler.toml` and deploy:

   ```toml
   routes = [{ pattern = "your-domain.com/*", zone_name = "your-domain.com" }]
   ```

5. Enable DNSSEC in Cloudflare → DNS → Settings. Then add the DNS-AID record
   (see `docs/agent-readiness.md`).

## Rollback

`wrangler delete ahmed-mokbel-agent-layer` — the site keeps working, it just
loses the edge features. Nothing in the repository depends on the Worker.

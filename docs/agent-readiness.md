# Agent readiness — audit and implementation record

This document records what the site publishes for AI agents, what it deliberately
does **not** publish, and why. It is the Phase 0 audit plus the deployment record.

Last updated: 2026-11-18 (build-generated APIs; this file is maintained by hand).

| Item | Finding |

### What GitHub Pages can and cannot do

Verified against the live host:

| Capability | GitHub Pages |
| --- | --- |
| Custom `Content-Type` per file | Only by extension. `.md` → `text/markdown`, `.json` → `application/json`, anything else → `application/octet-stream` |
| `Access-Control-Allow-Origin` | Always `*` — good for agent clients |
| `Link` response headers | **Impossible** |
| `Vary: Accept` | **Impossible** |
| Content negotiation (`Accept: text/markdown`) | **Impossible** |
| Server-side routing / JSON-RPC | **Impossible** |
| DNS records | **Impossible** — `github.io` is not the owner's zone |
| `Strict-Transport-Security` | Always sent (`max-age=31556952`) — not configurable |
| `Content-Security-Policy` | No HTTP header. A `<meta http-equiv>` subset is enforced live |
| `Referrer-Policy` | No HTTP header. `<meta name="referrer">` is enforced live |
| `frame-ancestors` | **Impossible** — browsers ignore it inside `<meta>` |
| `X-Content-Type-Options`, `X-Frame-Options`, `Permissions-Policy`, `COOP`, `CORP` | **Impossible** — no `<meta>` equivalent |

### Security headers: what is actually enforced

`build.py` injects the following into every public page, after `<meta charset>`:

- `Content-Security-Policy` via `<meta http-equiv>` — `default-src 'self'`,
  `script-src 'self'`, `style-src 'self' 'unsafe-inline'` (inline `style="…"`
  attributes are still used), `img-src 'self' data:`, `media-src 'self'`,
  `frame-src https://www.youtube-nocookie.com` (the lightbox YouTube embed),
  `connect-src 'self' https://api.web3forms.com` and
  `form-action 'self'` (the contact form is submitted as JSON), `base-uri 'self'`,
  `object-src 'none'`, `manifest-src 'self'`. `frame-ancestors` is deliberately
  omitted because it is ignored in `<meta>` and would only add a console warning.
- `Referrer-Policy: strict-origin-when-cross-origin` via `<meta name="referrer">`.
- `robots` (`index, follow, max-image-preview:large` on public pages; `noindex`
  on 404 and the admin area).

The contact form is submitted as JSON to `https://api.web3forms.com/submit`.
The public access key lives at `contact.web3formsAccessKey` in
`content/site.json`; while it is empty the form hides the provider and offers
the WhatsApp fallback instead.

`netlify.toml` in the repository root contains a fuller header set, but **it is
not read by GitHub Pages** and none of it is active on the live site. The
remaining hardening (X-Frame-Options / `frame-ancestors`, nosniff,
Permissions-Policy, COOP/CORP) needs either a host that supports response
headers or the Cloudflare Worker in `deploy/cloudflare/`.

## 2. What was implemented (static, no server)

Everything below is generated by `build.py` from `content/*.json` and is served by
GitHub Pages today.

| Path | Purpose |
| --- | --- |
| `/api/profile.json` | Identity, disciplines, location, studio, numbers, contact |
| `/api/projects.json` | All 24 projects with public slugs and detail URLs |

| `/api/services.json` | Six services with deliverables, audience, page + markdown URLs |
| `/api/health.json` | Build status and dataset counts |
| `/api/index.json` | Machine-readable index of the resources above |
| `/openapi.json` | OpenAPI 3.1 description of the read-only API |
| `/.well-known/api-catalog` | RFC 9727 linkset (also `.json` twin) |
| `/.well-known/ai-catalog.json` | ARD manifest, 6 entries, every URL live |
| `/.well-known/agent-skills/index.json` | 3 skills with real SHA-256 digests |
| `/skills/*/SKILL.md` | The skill documents those digests cover |
| `/.well-known/security.txt` | Real contact channel |
| `/auth.md` | Honest access statement: public, read-only, no registration |
| `/index.md` + 6 service `.md` files | Markdown mirrors of the human pages |
| `/docs/api/` | Human + machine readable API documentation |
| `/robots.txt` | `Content-Signal` policy + `Agentmap` pointer |

`Link`-equivalent discovery is also embedded in every page `<head>` as
`<link rel="api-catalog">`, `<link rel="service-doc">`,
`<link rel="describedby">` and `<link rel="alternate" type="text/markdown">`.

### WebMCP

`js/webmcp.js` registers five browser tools when the browser exposes
`document.modelContext` or `navigator.modelContext`:

`search_projects`, `get_project`, `list_services`, `get_profile`,
`start_project_inquiry`.

`start_project_inquiry` only pre-fills the contact form and scrolls it into view.
It never submits. The form carries `toolname` / `tooldescription` /
`toolparamdescription` attributes for the declarative API. In browsers without
WebMCP the script exits silently — no errors, no side effects.

## 4. What is not implemented, and why

| Requirement | Verdict | Reason |
| --- | --- | --- |
| OAuth / OIDC discovery (`/.well-known/openid-configuration`) | **NOT APPLICABLE** | There are no protected resources and no authorization server. Publishing issuer/token/JWKS metadata would be fabricated. |
| OAuth Protected Resource metadata | **NOT APPLICABLE** | Scanner reports "auth.md exists but OAuth Protected Resource Metadata was not found". Correct: RFC 9728 describes protection of a resource, and none is protected. |
| DNS-AID (`_index._agents.*`) | **NEEDS DOMAIN** | `github.io` is not the owner's DNS zone. Cannot create records or DNSSEC in a zone we do not control. |
| DNSSEC | **NEEDS DOMAIN** | Same. |
| MCP server card | **BLOCKED BY HOSTING** | Needs a request handler. Worker is written; card is served by the Worker, never statically. |
| Link headers | **BLOCKED BY HOSTING** | GitHub Pages cannot emit them. Worker is written. |
| Markdown negotiation | **BLOCKED BY HOSTING** | Cannot vary the response body by `Accept` on a static host. Mirrors exist; negotiation needs the Worker. |
| `Content-Type: application/linkset+json` on the extensionless path | **BLOCKED BY HOSTING** | Extensionless files are served as `application/octet-stream`. The `.json` twin carries the right type; the Worker fixes the extensionless one. |
| Agent registration endpoint | **NOT APPLICABLE** | No accounts exist. `auth.md` says so explicitly. |
| Commerce protocols (x402, UCP, ACP, MPP) | **NOT APPLICABLE** | The site sells no products and processes no payments. |

## 5. What would be fake, so it was skipped

- Any `openid-configuration` file with invented `jwks_uri` or `token_endpoint`.
- An `mcp/server-card.json` pointing at a `/mcp` path that returns 404.
- DNS-AID SVCB records the site cannot control.
- Placeholder SHA-256 digests in the agent-skills index — the published digests
  are computed from the actual files at build time and verified after build.
- An API catalog advertising endpoints that do not resolve.

### Why each remaining failure stays

- **`linkHeaders`** — GitHub Pages emits a fixed header set. The Worker in
  `deploy/cloudflare/` adds them (tested), but it is not deployed.
- **`markdownNegotiation`** — a static host cannot choose the response body from
  the `Accept` header. `/index.md` and the six service mirrors do exist and are
  served as `text/markdown`, so an agent can read Markdown today; what is missing
  is negotiation on `/` itself.
- **`mcpServerCard`** — the checker accepts only a card that points at a working
  MCP endpoint. The Worker serves both; neither exists until it is deployed.
- **`dnsAid`** — `github.io` is GitHub's zone, not the owner's. No SVCB record
  and no DNSSEC can be created there.
- **`oauthDiscovery` / `oauthProtectedResource` / `authMd`** — the scanner now
  reports `authMd` as *"auth.md exists but OAuth Protected Resource Metadata was
  not found"*. That is accurate: there is no protected resource, so under RFC 9728
  there is nothing to describe. Publishing a PRM document with an empty
  `authorization_servers` list purely to turn the check green would be a
  fabrication, so it was not done.

The maximum reachable level on GitHub Pages alone is **Level 2** for this site:
everything above that requires response-header control or DNS ownership.

## 7. Owner actions required

1. **Optional — buy a domain.** Without it, DNS-AID, DNSSEC and single-origin
   Link headers stay impossible.
2. **Set `meta.customDomain`** in `content/site.json`, rebuild, push. The build
   writes `CNAME` and rewrites every canonical/API URL. Do this only after DNS
   points at GitHub Pages, or the site goes down.
3. **Deploy the Worker** (`deploy/cloudflare/README.md`) to gain Link headers,
   markdown negotiation and `/mcp`.
4. **Enable DNSSEC** in Cloudflare once the domain is on Cloudflare.
5. **Add DNS-AID** once a domain exists:
   `_index._agents.<domain> IN SVCB 1 . alpn="h2" port="443"` (see the current
   DNS-AID draft; do not copy syntax from older revisions).
